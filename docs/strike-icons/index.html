Markup

<span class="strike strike-orange">
  <span class="strike-ring"></span>
  <span class="strike-glyph"><img src="lightning-orange.svg" alt=""></span>
</span>

Both inner spans are needed. .strike-glyph wraps the image so the drop animation and the white flash move together; .strike-ring stays outside it so the shockwave stays pinned to the strike point instead of being dragged down with the icon. Omit .strike-ring if you do not want the ring.

The colour class is required. The body colour comes from the SVG file, but .strike-orange / .strike-blue supply the ring colour, the glow colour, and which point the icon anchors to.

Opacity — how old a strike is

Your code sets this, not the CSS. Opacity depends on how far the strike is from the time you are showing, and CSS has no way to know that. Set it on the outer .strike element.

Age is measured against the time currently being displayed, not the wall clock, so scrubbing backwards through a timeline behaves the same as playing forwards.

AgeOpacity
0–5 min100%
15 min85%
30 min65%
60 min45%
over 60 minhidden — remove the element

Those four are anchor points, hit exactly at their own boundary. Values in between are interpolated, so a strike fades continuously rather than snapping down in four steps. Quantising to 1% stops you restyling every element on every frame.

const AGE_STOPS = [
  { min: 5,  opacity: 1.00 },
  { min: 15, opacity: 0.85 },
  { min: 30, opacity: 0.65 },
  { min: 60, opacity: 0.45 }
];

// null means do not show it at all: too old, or still in the future.
function ageOpacity(ageMin) {
  if (ageMin < 0 || ageMin >= 60) return null;
  if (ageMin <= 5) return 1;
  for (let i = 1; i < AGE_STOPS.length; i++) {
    const from = AGE_STOPS[i - 1], to = AGE_STOPS[i];
    if (ageMin <= to.min) {
      const t = (ageMin - from.min) / (to.min - from.min);
      return Math.round((from.opacity + (to.opacity - from.opacity) * t) * 100) / 100;
    }
  }
  return null;
}

The two glows — and why only the newest icons animate

There are two, doing different jobs. Keeping them straight is the whole design.

  • .strike-arrive — the animation. Ring, drop and white flash, about 2.9 seconds, then over. Add it only to strikes that landed on the tick you are currently rendering — the newest timestamp. Not to everything that happens to be young.
  • .strike-fresh — the static halo. A steady glow, nothing animating. Hold it for as long as the strike is under 5 minutes old, then drop it.

Why the animation is restricted to the newest timestamp: if you animated everything under 5 minutes old, then every time the clock moved you would re-fire dozens of animations at once, and a user jumping the timeline would trigger hundreds simultaneously. That is noise, not information. The animation answers "this just happened"; the halo answers "this is recent".

The halo is also the only thing that can answer the second question. Look at the ramp above: opacity sits flat at 100% for the whole 0–5 minute band, so a strike from 10 seconds ago and one from 5 minutes ago are pixel-identical. Without the halo, a strike you did not watch arrive is indistinguishable from one about to age out of the band.

The animation's final keyframe is the halo, so when .strike-arrive comes off, a still-fresh strike carries straight on with nothing visibly changing.

Driving it

// Every time the clock moves, for each strike on screen:
const ageMin = (displayedTime - strike.time) / 60000;
const opacity = ageOpacity(ageMin);
if (opacity === null) { remove(el); return; }   // too old, or in the future

el.style.opacity = opacity;
el.classList.toggle('strike-fresh', ageMin <= 5);

// Only when the element is first created, and only if the strike landed
// within this tick — that is what keeps the animation to the newest icons.
if (isNewElement && strike.time > previousTickTime) {
  el.classList.add('strike-arrive');
  el.addEventListener('animationend', ev => {
    // strike-bloom is the longest of the four, so it finishes last.
    if (ev.animationName === 'strike-bloom') el.classList.remove('strike-arrive');
  });
}

Let the animation remove its own class on animationend rather than clearing it on a timer. It runs longer than 5 minutes of data does at most playback speeds, so cancelling it when the strike ages would cut it off mid-flash.

If a user jumps the timeline by more than a few minutes, skip .strike-arrive entirely for that render — a jump mounts a whole backlog at once, and none of it "just happened".

prefers-reduced-motion is handled in the CSS: the animation is skipped, the halo still applies.
